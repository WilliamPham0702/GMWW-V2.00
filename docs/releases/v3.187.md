- Runtime V3.187; IPA shell vẫn 3.110. **Không phát hành IPA mới.**
- Không reset phòng, không xóa thành viên/ván hay thay phân bố seat và ảnh nền người dùng đã xuất bản.

## Pre-release gates
1. Review the PR changes and all GitHub CI checks, especially Check Player Web Worker, Check 30-Player Realtime Room, GR01 Backup Integrity and browser tests. **Only merge after SUCCESS.**
2. Confirm live /api/health and /api/update/manifest. Target must be strictly newer than production, 3.187 > 3.186.
3. Record currently serving Cloudflare Worker deployment/version IDs as rollback reference. Keep Durable Object storage intact; never delete or migrate data as part of this UI and DEMO release.
4. Ensure OTA package has the new **3.187** releaseVersion and verified SHA-256 checksums; prevent serving mismatched manifest and bytes.

## Release
- Merge release PR into main after success; standard `.github/workflows/check-player-web.yml` gates the `.github/workflows/deploy-production.yml` workflow.
- Let the existing deploy workflow create a checksum-verified OTA package and deploy via Wrangler. Do not bypass version guards.
- On success, confirm Production health V3.187, OTA manifest releaseVersion 3.187, assets and SHA-256, GET Player Web and GM Runtime.
- Confirm new **V3.187** note appears in the update manifest.

## iPhone acceptance checklist (GM)
- Open GMWW (existing IPA supported); apply/update Runtime OTA V3.187 when offered.
- DEMO 6, 12 and 30 players: verify event order in a night, newest on top, old events collapsed, no loss after reopen/pause, and no overlap with character interactions.
- At daybreak, verify all confirmed events, critical events first and red, translucent report, history/day sections still accessible after 10 seconds and audio not duplicated.
- PR #411: verify an actor killed in the same night still completes their action; death applies at dawn; Bảo Vệ, Phù Thủy, Yêu Tinh follow the updated demo rules.
- Confirm all existing seats/backgrounds/characters/player data remain intact.

## Rollback (if Production fails after deploy)
- **Do not roll back blindly during an ongoing night** with deferred-death effects from PR #411; finish/resume safe cycle first or assess the pending-death ledger to avoid state incompatibility.
- Restore the **previously recorded immutable Cloudflare Worker version** using controlled deployment-version rollback (or redeploy the known-good previous build and assets), not a destructive storage reset.
- Re-verify Worker health and Player Web; retain Durable Object storage and GR01/PITR safeguards. Prior OTA clients upgraded to V3.187 may not accept automatic version downgrade: provide an explicit repaired forward version if needed.
- Record incident and rollback deployment/version IDs in the task notes.
